حزمة المتجر التقني المتكاملة
============================

المحتويات
- index.html: واجهة المتجر العامة.
- admin/index.html: لوحة الإدارة.
- assets/css/style.css: التصميم المتجاوب والثيم التلقائي.
- assets/js/config.js: إعداد الاتصال بـ Supabase.
- assets/js/store.js: وظائف واجهة المتجر.
- assets/js/admin.js: تسجيل الدخول وإدارة البيانات ورفع الصور.

قبل النشر
1) افتح assets/js/config.js.
2) اترك supabaseUrl كما هو؛ فهو عنوان مشروعك الحالي.
3) تم تضمين عنوان مشروع Supabase ومفتاح Publishable العام الحالي في config.js. لا تضع service_role أو أي Secret key في ملفات الواجهة.
4) ارفع محتويات المجلد إلى جذر مستودع GitHub المرتبط بموقع Netlify، مع الحفاظ على المسارات.
5) إعدادات Netlify: Build command فارغ، وPublish directory = .
6) بعد اكتمال النشر افتح https://husam-store.netlify.app/ad لتسجيل الدخول بحساب المدير الموجود في Supabase Auth.

وظائف المتجر
- قراءة بيانات المتجر والتصنيفات والمنتجات والصور والعروض والأخبار والخدمات والروابط الاجتماعية.
- البحث والتصفية حسب تصنيف المنتجات.
- تفاصيل المنتج وطلبه عبر WhatsApp برسالة تشمل المنتج والسعر الحالي والكمية والإجمالي ورابط المنتج.
- السعر المخفض يطبق فقط عند وجود عرض نشط مرتبط بالمنتج وضمن تاريخ البداية والنهاية.
- إرسال رسائل العملاء (الاسم والهاتف والرسالة فقط؛ البريد الإلكتروني غير مطلوب) إلى contact_messages.
- أزرار إعجاب/مفضلة للمنتجات والعروض والأخبار والخدمات؛ تحفظ اختيارات الزائر في متصفحه باستخدام LocalStorage ولا تحتاج إلى تعديل قاعدة البيانات.
- المظهر تلقائي وفق إعدادات مظهر الجهاز (prefers-color-scheme)، ولا يوجد زر تبديل يدوي.

وظائف لوحة الإدارة
- تسجيل الدخول عبر Supabase Auth والتحقق من role = admin في profiles.
- لوحة أرقام مختصرة.
- إضافة وتعديل وحذف المنتجات والتصنيفات والعروض والأخبار والخدمات وروابط التواصل.
- رفع صور إلى product-images وnews-images وservice-images وstore-assets.
- متابعة رسائل العملاء وتغيير حالة القراءة؛ لا يظهر حقل البريد في نموذج التواصل أو قائمة الرسائل.
- تعديل بيانات المتجر ورقم واتساب وبيانات الاتصال والشعار.

ملاحظات مهمة
- لا تُنشئ الجداول أو سياسات RLS من جديد؛ الحزمة تستخدم الجداول الحالية: categories, products, product_images, offers, news, services, site_settings, social_links, profiles, contact_messages.
- يتطلب عمل لوحة الإدارة أن يكون المستخدم مسجلاً في Auth وله صف في profiles بدور admin، وأن تكون سياسات RLS الحالية تسمح للمدير بالعمليات الإدارية.
- رفع الصور يستخدم Storage buckets الموجودة لديك بالأسماء المحددة أعلاه.
- عند حذف منتج، تحذف صور product_images التابعة له تلقائياً وفق ON DELETE CASCADE. ملفات Storage نفسها لا تُحذف تلقائياً من هذه الواجهة، لتجنب حذف ملفات مستخدمة بالخطأ.
- تأكد من إدخال رقم واتساب بصيغة دولية مع رمز الدولة، مثل 9677xxxxxxx، من إعدادات المتجر.
- إذا كان اسم عمود أو سياسة RLS في مشروعك مختلفاً عن المخطط الذي أنشأناه سابقاً، ستظهر رسالة الخطأ في لوحة الإدارة أو Console.

الاختبار
تم فحص صياغة ملفات JavaScript محلياً باستخدام Node.js. لم يتم اختبار تسجيل الدخول أو عمليات CRUD ورفع الملفات على الموقع المنشور بعد؛ يلزم اختبارها بعد اكتمال النشر.

تنبيه بخصوص الإعجابات
- الإعجاب الحالي يعمل كمفضلة شخصية محفوظة في المتصفح والجهاز نفسه. لا ينشئ عداد إعجابات عاماً ولا يرسل بيانات الإعجاب إلى Supabase. إذا أردت إحصاءات إعجاب مشتركة بين الزوار، فذلك يتطلب إضافة جدول وسياسات RLS مخصصة لاحقاً.
